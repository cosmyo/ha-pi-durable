# Architecture (0.1.0)

Browser → authenticated Node server → one Pi Durable 1.0.0 harness/SQLite store; a narrow HA REST client is separate from the model provider. The Docker context is `hearth_pi/`; Supervisor supplies root-owned `/data/options.json` and `SUPERVISOR_TOKEN`. Startup reads options, restricts `/data` and known SQLite files, then drops to UID/GID 1000 before opening the harness/network service. Container permissions and real Supervisor lifecycle remain untested.

`Runtime.open` opens exclusive SQLite WAL ownership and checks `synchronous=FULL`; it initializes the registry/documents, invalidates pending proposals and marks dispatching ones unknown, drains input reservations and resumes the harness. Persisted catalogue owns session IDs and owner IDs; input requests bind idempotency keys to a content hash. Input reservation and harness submission are distinct commits: restart drains the gap. An admitted input is stored before HTTP 202. The upstream harness stores tasks, entries and checkpoints; SSE emits full current snapshots, not a replayable event log. Reconnect hydrates current state; up to four active conversations and bounded history/streams/turns protect resources. Safe model/read work can rerun on restart and consume provider tokens.

Tools: `ha_search_states` (20 per page, scoped output), `ha_state_detail`, `ha_discover_services` (live allowlist intersection), `ha_propose_service` (no POST). The HA REST token has wider access than scoped tool results. Proposals are immutable action+session+task hash, policy digest and five-minute expiry. Human approval revalidates live service/entity and policy, commits `dispatching` before one POST; HTTP success records `accepted`, failure/timeout records `unknown`. A crash leaves `unknown` at startup; pending approval is invalidated. `resolved` is a human note, not proof of physical outcome. No model-callable execution tool and no automated mutation replay.

Server routes check the socket peer and explicit Ingress user allowlist, or loopback Basic auth in local mode. Owner checks apply to sessions and their SSE/snapshots/actions. POST needs same-origin and browser-bound CSRF capability. Rendered untrusted strings use text nodes. OpenAI key and Supervisor token remain backend-only; only a restricted faux offline provider or official OpenAI API-key adapter is configured. See [security](security.md) and [validation](validation.md) for guarantees and untested boundaries.
