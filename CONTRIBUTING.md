# Contributing

Read [AGENTS.md](AGENTS.md), [architecture](docs/architecture.md), [security](docs/security.md) and [validation](docs/validation.md) before proposing changes. This is an independent experimental App; keep patches small and preserve its fail-closed boundaries. No live-system testing, remote creation, publishing or dependency/code copying without authorization.

Use Node 24.21.0. From a clean checkout run `npm ci`, `npm --prefix hearth_pi ci`, then `npm run check`. Run `npm run format` after edits; the pinned formatter is checked by the validation gate. The Hearth Assist integration (`custom_components/hearth_pi`) has its own tests: in a local virtual environment that is never committed (for example `.venv-ha/`), install `pytest-homeassistant-custom-component` plus the `conversation` integration's requirements and run `python -m pytest tests/hearth_pi_integration`. After any UI or CSS change run the touch-target audit (`node scripts/touch-targets.mjs`, see [validation](docs/validation.md#touch-target-audit-ui-changes)): every control must be at least 44x44 CSS px at 390 and 360 px wide, standalone and embedded. Add synthetic tests for changed behavior (especially admission/recovery, peer/owner checks and mutation outcomes). CI configuration does not establish that any remote run passed. Docker/container and real Supervisor testing require a separate authorized isolated environment.

Do not commit secrets, personal options, runtime databases, transcripts or real HA snapshots. Use `.example` domains and synthetic identities. Do not add generic network, shell, filesystem, configuration or administrative agent tools; changes to permissions, provider auth and action dispatch need threat-model review. Confirm licenses and retain notices before importing third-party code or artwork; ideas are not a license to copy. Include a concise rationale, tests, deployment limitations and user-facing docs with any contribution.
