# Installation and configuration (experimental)

Use only an **authorized, isolated test Home Assistant installation**. No live installation, Docker image execution or Supervisor Ingress integration has been verified by this project. No public App repository URL or prebuilt image exists. To build locally, see [validation](../docs/validation.md). With an approved local installation, copy the complete `hearth_pi/` directory as `/addons/hearth_pi`, then in **Settings → Apps → App store → Check for updates → Local apps → Hearth Pi** install, configure, start and open the Web UI. Older Home Assistant versions may label Apps as Add-ons. This is an installation procedure, not a claim it has been performed.

## Required options

- `authorized_user_ids`: explicit Home Assistant user IDs permitted to reach the backend. Default `[]` denies all. Ingress identity comes from the verified proxy peer and `X-Remote-User-Id`; `panel_admin` only hides/shows navigation and does not prove current admin role or revocation status. Obtain IDs through authorized administration; never guess from display names.
- `public_origin`: exact HTTPS origin of the Home Assistant UI, no trailing path (example `https://home.example`). Required for mutation Origin checking and iframe policy. Test in the target proxy/mobile setup before enabling actions.
- `allowed_entities`: exact HA entity IDs visible to reads and eligible for approved service actions. Default empty; this App does not inherit Assist exposure filtering. State search fetches a capped HA states response before filtering, so this scope limits output, not backend access to HA data.
- `provider`: `offline` is a credential-free faux response, **not a local LLM**. `openai` needs a server-side `openai_api_key` and catalog `model` (initial default `gpt-4.1-mini`). OpenAI receives user conversation/context and selected HA tool data. No live paid inference was exercised. Keep the key private; Supervisor options/backups contain it. OAuth, voice and custom/local provider URLs are unsupported.
- `service_actions_enabled`: default false. If enabled, configure `allowed_services` with only `light.turn_on`, `light.turn_off`, `switch.turn_on`, `switch.turn_off` as needed, plus matching `allowed_entities`. The assistant may propose; a human explicitly reviews and approves exact action/hash. `light.turn_on` alone can include bounded `brightness`; no area/device/group/indirect selectors. A successful HTTP call is **not** verified device state.

`homeassistant_api: true` is a broad backend token, not per-user permissions. Keep defaults until read and approval behavior have been reviewed in isolation. The App exposes Ingress only, no host ports or HA config mount. `/data` persists across restart/update but not uninstall; cold backups may restore old state. Restore replaces current data: investigate unknown actions and obtain fresh proposals; interrupted writes are never retried automatically. See [security](../docs/security.md).
