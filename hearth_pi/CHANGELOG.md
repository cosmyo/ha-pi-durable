# App changelog

## Unreleased — installation, Home companion, permissions and model selection

Admin access mode (source slice, opt-in): set `access_mode: admin` in the App configuration to let Hearth read all of Home Assistant and propose any service call, automation/script/scene change, registry/helper change or allowlisted Supervisor action. Every change is classified low/medium/high/critical; Full access runs only low ones (medium when the optional cheap risk judge agrees), high and critical always ask, and critical needs you to type a confirmation word. Choose the judge with `risk_judge_model` (default `auto`) — including a small model on a private llama.cpp server via `endpoint/<model>` and `risk_judge_url`. Automation and script writes always ask in admin mode; Home World and app buttons also work for fans, climate, covers, media players, automations, helpers, humidifiers, vacuums and locks (risk rules decide whether a press runs or asks). Supervisor actions (add-ons, backups, Core/OS/Supervisor updates, host power) go straight to Supervisor's own API with the add-on's manager role, granted in every installation and never admin, instead of through Home Assistant Core, which does not accept the add-on's connection for that; Hearth's own allowlists stay the real limit on what it can do. A Supervisor action Supervisor definitely refused before anything happened now shows as failed rather than unknown, so it never blocks you from trying something else. Scoped mode is unchanged and never touches Supervisor's API.

Set up your Home World with Hearth (source slice): ask “Set up my home view” in a Home chat and attach a floor-plan photo or screenshot with the new **＋** button. Hearth reads your house, asks unclear points in one batch and proposes a layout as a **preview** — a card in the chat opens it in Home World with **Keep** and **Discard**; nothing is saved until you keep it and your Home Assistant areas are never changed. Attached images stay in your Hearth data, go only to the chat's model provider and show as thumbnails in the chat; text-only models refuse images with a clear message.

Household memory and suggestions (source slice): **Settings → Memory** lists the facts and preferences you approved ("Bedtime is around 23:00", "Study fan is called Breezy") with Add, Edit and Forget; Home chats get them as clearly marked owner-approved context that can never grant permissions or override safety rules (at most 4 KB, oldest trimmed first with a warning). Hearth can _suggest_ a memory or an app change; suggestions appear at the top of **Today** with Accept, Edit, Reject and Snooze and nothing changes until you accept. A stale app suggestion shows a conflict instead of applying. Rejected ideas are not suggested again for 60 days. After a 👎 with a reason in a chat that built an app, Hearth may offer a fix on your next message there.

Navigation simplification and UX audit: the drawer footer now has at most three rows \u2014 **Today**, **Apps** and **Settings** (one compact status line, e.g. "Ask \u00b7 ChatGPT \u2713 \u00b7 Claude \u2713") \u2014 instead of six. **Settings** opens one grouped sheet (iOS-Settings style) with Home permissions, Account, Briefings & watchers, Insights, Home World (prototype) and a new **About** panel (version, provider, the "independent/experimental" notice); every target dialog keeps its existing id and behavior, only its entry point moved. The permission badge next to the conversation title still opens Home permissions directly. Fixed: short landscape phones could leave the drawer footer unreachable with no inner scroll; sheets now scroll internally on every screen size, not only the compact breakpoint; compact-layout buttons had shrunk below the 44px touch-target minimum (now 44px everywhere, including session-menu rows and app tabs). Today's empty state now explains what watchers and briefings are and offers **Create a watcher**, which opens the add-watcher form directly; an empty Apps list now offers four one-tap starting templates (Laundry, Bedtime lock-up, 3D print monitor, Maintenance checklist) that draft a "Make me a \u2026 app" message instead of a blank chat.

Automation troubleshooting (source slice): for automations you add to `allowed_entities`, Hearth can read their config, recent traces, logbook and history to explain why they did or didn't run, and draft corrected YAML for you to paste yourself. It cannot change automations or any configuration. Entities outside the read scope are named, not read; secrets are redacted and `!secret` refs stay literal.

Proactive Home (source slice): watchers on apps or your own, morning/evening briefings (off until you turn them on) and a **Today** inbox of cards with values Hearth read and their times. Watchers and briefings only read in-scope entities and add cards; they never control devices or start a chat. A reminder missed while Hearth was off arrives once, marked late. Rate replies with 👍/👎 and see them under **Insights** (no message text is stored).

Apps on demand (source slice): Hearth can build small household apps from a Home chat as validated declarative HAS/1 specs. Every value is read by Hearth with an as-of time; checklist ticks, counters and notes are kept separately from versions; toggles use Home permissions and are never retried after an unknown outcome. Open them from **Apps** in the drawer or pin them to empty chats.

Default-off Anthropic `/login` feature flag with native Pi headless copy-code auth, private per-provider tokens and pinned pi-anthropic-auth 3.4.2 transport compatibility. HA option fallback allows deliberate installation opt-in without changing provider/scope/permissions. Experimental third-party subscription terms/extra-billing warnings; not a live Claude inference claim.

Chat transcript polish: a turn's tool calls and their results now collapse into one compact, collapsed-by-default "activity" row with a friendly verb (e.g. "Searched home") instead of raw `tool_name {...}` lines and huge JSON blocks pushing the reply down; known Home/app/catalog/coding tools map to friendly labels and unknown ones still show their raw name. Errors stay visible in the row's summary even while collapsed, and long tool results truncate with "Show more". Assistant replies render as plain, calm text with a small "Hearth" label and a Copy button instead of a bordered card; user messages stay as compact right-aligned bubbles. A floating "\u2193 New messages" pill appears only while scrolled up and new content arrives; the transcript still sticks to the bottom automatically when already there. A single animated "Working\u2026" line (off under `prefers-reduced-motion`) replaces one row per in-progress tool call.

One-click repository link and App-store/sidebar setup instructions. Native Home canvas over exact approved entities; Read-only (default) / Ask / explicitly acknowledged Full access Home permissions for exact light/switch policies; durable per-session model/thinking selector; a UI-connected private-network local model endpoint (`provider: local`); ChatGPT login follows Pi's interactive `/login` steps with token expiry and **Check connection**. Bounded exact-entity scopes and pagination support larger homes. A compact phone/companion-app layout keeps the conversation on screen, with Home permissions and model settings opened on demand. A session can now be deleted from its conversation header after owner confirmation; it is removed from the list and session limits and its routes answer 404, but deletion is refused while an action proposal, running task, unanswered input or paused coding workspace is still unresolved, and the stored transcript itself is not securely erased. Empty scope still denies all, service actions remain disabled by default, and Code-worker provisioning is still separate. The App version remains 0.2.0 until a tagged release.

## 0.2.0 — experimental subscription/coding preview

ChatGPT/Codex OAuth through official Pi 1.0.1 with private credential storage/headless login; separate constrained no-network regular-Pi workspace, explicit Home/Code scope and no automatic coding replay/reissue. Coding is disabled by default and requires an externally installed worker and exactly one trusted operator. No Core configuration/admin privileges. See DOCS and validation for human-login/target-system evidence and limitations.

## 0.1.0 — experimental initial implementation

Initial Ingress App source: SQLite-backed Pi Durable sessions, scoped HA reads, optional reviewed light/switch actions, offline demonstration and OpenAI API-key mode. Not a published image or tested Supervisor deployment. See [validation](../docs/validation.md).
